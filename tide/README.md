# 潮汐 · 基于 Oura Ring 的释放时机管理

一个装在手机上的 PWA（可加到主屏幕），读你的 Oura 数据（Readiness、睡眠、夜间 HRV、体温偏差、压力、最佳就寝窗口），给出**今天适不适合、什么时段最好、什么时候该休息**，并按时提醒。目的不是"多"或"少"，而是把它放到对睡眠、专注和恢复最有利的位置，顺手把作息管住。

它做三件事：

1. **逐时评分**：每天 24 个小时槽各打一个 0–100 分，综合作息（起床/就寝/专注时段）、身体状态（Oura 当日数据 vs 你的 14 天基线）、间隔（距上次多久）。
2. **个人学习**：你每记一笔，它把随后那一夜的睡眠分、入睡时长、夜间 HRV、次日 Readiness 与你的基线对比，按时段和间隔分桶，找出**对你**最有利的时机，并反馈到评分里。
3. **提醒**：最佳窗口开始、睡前 30 分钟收尾、就寝时间、冷却期结束、"今天休息"。三种通道：页面内通知、服务器 Web Push（关掉页面也能收到）、导出 .ics 到日历。

## 快速开始（先看演示，不用戒指）

```sh
cd tide
npm install
npm start          # http://localhost:8787
```

打开后进「设置」→ 勾选「演示模式」，会灌入 30 天合成数据和 9 条示例记录，四个页面都能看到真实效果。

## 连接 Oura（真实数据）

Oura 在 2025 年 12 月停发了 Personal Access Token，新接入只能走 OAuth2，所以需要一个小服务器保管 token（本仓库自带，零外部依赖，只有 `web-push` 一个可选包）。

1. 去 <https://cloud.ouraring.com/oauth/applications> 新建应用。**Redirect URI** 填 `http://localhost:8787/auth/callback`（部署到别处就换成你的公网地址 + `/auth/callback`）。勾选 scope：`daily`、`heartrate`、`stress`、`tag`。
2. 复制 `.env.example` 为 `.env`，填入 `OURA_CLIENT_ID`、`OURA_CLIENT_SECRET`，按需改 `PUBLIC_URL`、`TZ`、`DAILY_PLAN_AT`。
3. `npm start`，打开页面 →「设置」→「用 Oura 账号登录」。授权后回到页面，右上角显示「Oura 已连接」。token 到期前服务器会自动用 refresh token 续期（Oura 的 refresh token 一次性，换完立即落盘）。
4. 「设置」→ 填好起床/就寝/专注时段/间隔 → 保存。这些会同步到你自己的服务器，用于每日自动计划。

### 让它在你不开页面时也提醒

- 服务器每天 `DAILY_PLAN_AT`（默认 08:30）自动拉 Oura、算当日计划、推一条「今天：适合/等待/休息」，并把当天的提醒排进队列按时推送。
- 前提是浏览器订阅了推送：「设置」→「订阅推送」。**Web Push 和 PWA 安装都要求 HTTPS**（`localhost` 例外）。放到家里的小机器或 VPS 时，前面套一层 Caddy / Cloudflare Tunnel / Tailscale Funnel 之类拿到 HTTPS，`PUBLIC_URL` 填 HTTPS 地址，并把 Oura 应用的 Redirect URI 同步改掉。
- iOS 需要先「添加到主屏幕」再订阅推送（iOS 16.4+）。
- 对外暴露时设置 `APP_PASSWORD`，接口需要口令；在「设置」→「访问口令」填一次即可。

### 没有服务器？静态模式

把 `public/` 直接丢到 GitHub Pages 也能跑（页面检测不到 `/api/config` 就切到静态模式）。此时用 Oura 的 implicit 授权（30 天有效、无 refresh），在「设置」填 Client ID 授权即可；Redirect URI 填你的 Pages 地址。**限制**：浏览器直连 `api.ouraring.com` 是否被 CORS 放行我没能在沙箱里验证；被拒的话会有明确提示，改用服务器模式。静态模式没有 Web Push，用「导出到日历」代替。

## 评分逻辑与证据等级

每个小时槽从 40 分起算，落在睡眠时段为 0。修正项：

| 因素 | 分值 | 依据 | 证据 |
|---|---|---|---|
| 距就寝 20–180 分钟，峰值在 80 分钟前 | 最高 +35（助眠模式 ×1.2） | 高潮后催乳素、催产素上升，交感兴奋回落，问卷与小样本研究报告入睡更快、主观睡眠更好 | 中 |
| 距就寝 < 20 分钟 | −5 | 清理、清醒会把入睡往后推 | 常识 |
| 起床后 30–120 分钟 | +6 | 晨间睾酮与精力处于日内高位 | 弱 |
| 专注时段内 / 其前 90 分钟 | −35 / −25（专注模式 ×1.3） | 高潮后短时动力与警觉下降 | 弱 + 常识 |
| 已过就寝时间 | 封顶 8 | 推迟入睡 | 强（间接） |
| Readiness ≥85 / 60–69 / <60 | +8 / −8 / −20；<50 直接「休息」 | Oura 的综合恢复指标 | 中 |
| 体温偏差 ≥ +0.5°C / ≥ +0.3°C | −40 并「休息」 / −12 | Oura 对生病、炎症的信号 | 强（间接） |
| 夜间 HRV 比 14 天基线低 20% / 高 10% | −12 / +5 | 自主神经恢复不足 | 中 |
| 最低心率比基线高 8% | −10 | 同上 | 中 |
| 昨晚睡眠分 < 60 | 白天 −12，睡前 +8 | 白天精力差；今晚可用作助眠 | 弱 |
| 昨日压力日「stressful」 | 睡前 +8 | 释放的放松作用 | 弱 |
| 长期韧性「limited」 | −8 | 优先恢复 | 弱 |
| 未到最短间隔 | 封顶 20 | 你设定的规则 | — |
| 达到目标间隔 / 两倍 | +8 / +12 | 你设定的规则 | — |
| 个人学习修正 | ±15 内 | 你自己的数据（见下） | 因人而异 |

结论：`休息`（体温高或 Readiness < 50）→ `等待`（冷却期内且剩余时段都差）→ `适合`（最佳窗口 ≥ 60）→ `可以`（45–59）→ `不建议`。

**坦白说**：关于频率和时机，可靠的对照研究很少。"睡前有助入睡"是证据最强的一条；"禁欲提升睾酮"那类说法效应很小且短暂。这个引擎真正靠谱的部分是 Oura 的恢复/生病信号和你自己的 n-of-1 数据，规则表只是起点。

### 个人学习怎么算

- 每条记录 → 影响的那一夜（凌晨 5 点前的记录算前一晚）→ Oura 那一夜的睡眠分、入睡时长、夜间 HRV、深睡、最低心率，以及次日 Readiness。
- 基线 = 近 30 天里"非记录之夜"的中位数。每条记录得到相对基线的差值。
- 按时段（早晨 / 午后 / 傍晚 / 睡前 / 深夜）和间隔（<24h / 1–2 天 / 2–4 天 / >4 天）分桶。综合分 = 睡眠分Δ + ReadinessΔ − 入睡Δ/2 + HRV 相对Δ%×0.3 + 深睡Δ/10。
- 桶内 ≥3 次才给结论，≥4 次才把 `综合 × 0.6`（限 ±15）加回评分。数据不足时页面会直说。

## 数据与隐私

记录只存在你的浏览器 localStorage；服务器模式下同步到**你自己**运行的服务器 `data/` 目录，用于每日推送。Oura token 只在服务器上。没有任何第三方服务。「设置」里可以导出/导入 JSON、一键清空。

## 已知限制

- Oura 的当天数据要等戒指同步到 Oura App 后才会出现在 API；早上还没同步时页面会提示并沿用最近一天。
- 页面内通知只在页面打开时触发；要可靠提醒请用服务器推送或日历。
- 单用户设计：一个服务器对应一个 Oura 账号。
- 这不是医疗建议。体温偏高、Readiness 很低时它会让你休息，但生病请看医生。
